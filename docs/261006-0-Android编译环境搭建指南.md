# PiliPlus Android 客户端编译环境搭建指南

> 目标：在 Windows 上从零搭建工具链，编译出 PiliPlus 的 Android APK
> 依据：`.github/workflows/build.yml`（CI 的 android job）、`android/` 构建配置、`lib/scripts/*.ps1`

## 0. 版本要求总览

| 组件 | 版本 | 依据 |
|---|---|---|
| Flutter | **3.47.6**（锁死，stable） | `pubspec.yaml` 的 `flutter: 3.47.6`、`.fvmrc` |
| JDK | **17** | CI 用 zulu 17；`android/build.gradle.kts` 强制 JVM 17 |
| Android SDK | compileSdk / targetSdk = **37** | `android/app/build.gradle.kts` |
| NDK | 由 Flutter 3.47.6 指定（构建时会报出确切版本号） | `ndkVersion = flutter.ndkVersion` |
| Gradle | 9.5.0（wrapper 自动下载） | `android/gradle/wrapper/gradle-wrapper.properties` |
| AGP / Kotlin | 9.1.0 / 2.4.0（构建脚本自带，无需手动装） | `android/settings.gradle.kts` |
| PowerShell | 7（本机已装 `C:\Program Files\PowerShell\7`） | 补丁脚本需要 |

## 1. 关于安装路径的重要提醒

**不要把 Flutter SDK 或 Android SDK 装进 `C:\Program Files`**，原因：

- 路径含**空格**，Flutter 工具链会明确警告，Gradle/NDK 的某些 native 工具在带空格的路径下会直接失败
- `Program Files` 需要管理员权限写入，而本项目必须对 Flutter SDK 源码**打 git 补丁**（见第 5 步），权限问题会让补丁流程变得麻烦

推荐路径（本文档以此为例）：

```
D:\Programs\AndroidSDK\flutter        # Flutter SDK
D:\Programs\AndroidSDK    # Android SDK
```

## 2. 安装 JDK 17

任选其一（winget 一行搞定）：

```powershell
winget install Microsoft.OpenJDK.17
# 或与 CI 一致的 Zulu：
# winget install Azul.Zulu.17.JDK
```

验证：新开终端执行 `java -version`，应显示 17.x。

## 3. 安装 Android SDK（不装 Android Studio 的纯命令行方案）

1. 下载 Command line tools：
   https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip
   （页面：https://developer.android.com/studio#command-tools）

2. 解压，使目录结构为（注意 `latest` 这层目录是 sdkmanager 的硬性要求）：

   ```
   D:\Programs\AndroidSDK\cmdline-tools\latest\bin\sdkmanager.bat
   ```

3. 配置环境变量（用户级）：

   ```powershell
   setx ANDROID_HOME "D:\Programs\AndroidSDK"
   # 并把 D:\Programs\AndroidSDK\platform-tools 追加到用户 PATH
   ```

   > 此时 `platform-tools` 目录还不存在是正常的，它在下一步由 sdkmanager 下载创建；PATH 可以先配上，装完即生效

4. 新开终端，安装必需组件并接受协议：

   ```powershell
   sdkmanager --licenses        # 一路 y
   sdkmanager "platform-tools" "platforms;android-37.0" "build-tools;36.0.0"
   ```

   > 注意：API 37 起平台包名带小版本号，是 `platforms;android-37.0` 而不是 `platforms;android-37`，用后者会报 `Failed to find package`
   > build-tools 具体小版本可先 `sdkmanager --list` 看可用的最新版，选最新的装即可

5. NDK 先不装，等第 7 步首次编译时按报错提示的确切版本安装（Flutter 各版本钉死的 NDK 不同，提前装容易装错版本）

## 4. 安装 Flutter 3.47.6（必须用 git clone）

**不能用官网 zip 解压版**——第 5 步要对 SDK 源码执行 `git apply` / `git reset --hard`，SDK 必须是 git 仓库且精确停在 3.47.6：

```powershell
git clone -b 3.47.6 --depth 1 https://github.com/flutter/flutter.git D:\Programs\AndroidSDK\flutter
```

> `--depth 1` 可以省空间；补丁脚本只做 `git apply` 和 `git reset --hard HEAD`，浅克隆够用
> 如果浅克隆的 tag 拉取有问题，去掉 `--depth 1` 全量克隆

配置环境变量：

```powershell
setx FLUTTER_ROOT "D:\Programs\AndroidSDK\flutter"
# 并把 D:\Programs\AndroidSDK\flutter\bin 追加到用户 PATH
```

新开终端验证（首次运行会下载 Dart SDK 等，较慢）：

```powershell
flutter doctor -v
flutter config --android-sdk "D:\Programs\AndroidSDK"
flutter doctor --android-licenses   # 全选 y
```

确保 `flutter doctor` 的 Android toolchain 一项无报错。

## 5. 关键步骤：给 Flutter SDK 和依赖包打补丁

本项目对 Flutter 框架源码做了约 25 处修改（bottom sheet、文本选择、滚动行为等），**不打补丁编译会失败或行为异常**。补丁脚本为 `lib/scripts/patch.ps1`，它做三件事：

1. 在 `$FLUTTER_ROOT` 内 `git apply` 一批 `.patch`（Android 平台共 25 个）
2. `flutter pub get` 拉依赖
3. 对 pub-cache 中的 `material_ui-*`、`cupertino_ui-*` 包再打一批补丁

### 5.1 运行前的环境适配（CI 脚本在 Linux 上跑，本机需要两点调整）

**调整一：pub-cache 路径**。脚本里 pub-cache 写死为 `~/.pub-cache`（只有传 `windows` 参数才改，但传 `windows` 会跳过 Android 专属补丁，不能用）。Windows 上 Flutter 的 pub 缓存默认在 `%LOCALAPPDATA%\Pub\Cache`，最省事的做法是建一个目录联接（junction），不用改环境变量、也不用重新下载依赖：

```powershell
New-Item -ItemType Junction -Path "$env:USERPROFILE\.pub-cache" -Target "$env:LOCALAPPDATA\Pub\Cache"
```

> junction 不需要管理员权限；以后想移除直接 `Remove-Item "$env:USERPROFILE\.pub-cache"`，只删联接本身
> 如果之前已经跑过一次脚本并在这里报错（`Cannot find path ... .pub-cache`），建完 junction 直接重跑脚本即可，重复运行是安全的

**调整二：脚本依赖两个 CI 环境变量**，运行时临时设置即可：

```powershell
$env:GITHUB_WORKSPACE = "E:\Data\BJTU\NJU5\5.PiliPlus"   # 仓库根目录
$env:FLUTTER_ROOT     = "D:\Programs\AndroidSDK\flutter"                  # 第 4 步 setx 过的话新终端已存在
```

> 另外脚本开头会执行 `git config --global user.name/email "ci"`（cherry-pick 的副作用），介意的话运行后自行改回

### 5.2 运行补丁脚本

```powershell
cd E:\Data\BJTU\NJU5\5.PiliPlus
pwsh lib/scripts/patch.ps1 android
```

每个 patch 应用成功会打印 `xxx applied`。若中途抛错，绝大多数情况是 **Flutter SDK 版本不对**（patch 上下文对不上），回到第 4 步确认 `git -C D:\Programs\AndroidSDK\flutter describe --tags` 精确为 `3.47.6`。

> 重复运行前需先还原 SDK：`git -C D:\Programs\AndroidSDK\flutter reset --hard HEAD`（脚本对 android 分支已自带这一步）

## 6. 生成版本信息文件（可选但推荐）

CI 用 `lib/scripts/build.ps1 android` 生成 dart-define 文件 `pili_release.json`（版本号、构建时间、commit hash）。不生成也能编译——`lib/build_config.dart` 里有默认值兜底（版本显示为 `SNAPSHOT`）。

```powershell
pwsh lib/scripts/build.ps1 android
```

> 注意：该脚本会把 `pubspec.yaml` 的 version 改写成 `2.1.6-<commit前9位>+<提交数>`，属于构建副作用，提交代码前记得还原这个文件

## 7. 编译 APK

```powershell
# Release，按 ABI 分包（推荐，与 CI 一致）：
flutter build apk --release --split-per-abi --dart-define-from-file=pili_release.json

# 或跳过第 6 步直接编译（版本号显示 SNAPSHOT）：
flutter build apk --release --split-per-abi

# 调试包：
flutter build apk --debug
```

产物位置：

```
build\app\outputs\flutter-apk\app-arm64-v8a-release.apk     # 现代手机装这个
build\app\outputs\flutter-apk\app-armeabi-v7a-release.apk
build\app\outputs\flutter-apk\app-x86_64-release.apk
```

说明：

- 仓库里没有 `android/key.properties` 签名配置时会自动退回 debug 签名（`android/app/build.gradle.kts:65`），可直接安装自用，但不能覆盖安装官方签名版本
- `gradlew` / `gradle-wrapper.jar` 被 `.gitignore` 排除了，首次 `flutter build` 时 Flutter 工具会自动生成，无需手动处理
- debug 包自带 `.debug` 后缀的 applicationId，可与 release 共存；加 `--android-project-arg dev=1` 则构建 `PiliPlus dev`（`.dev` 后缀）

### 关于 NDK

实测 Flutter 3.47.6 的工具链会在首次编译时**自动下载安装所需 NDK**（本项目为 NDK 28.2 / r28c，日志里会出现 `Installing NDK (Side by side) 28.2`），无需手动干预。

如果自动下载失败，再手动补装：

```powershell
sdkmanager "ndk;<报错或日志中的版本号>"
```

另外首次编译日志里每个插件都会出现 `Warning: Overriding compileSdk version ... to 36`，这是项目 `android/build.gradle.kts` 里写死的兼容逻辑，纯提示，忽略即可。`assembleRelease` 阶段首次运行 10~30 分钟属正常。

## 8. 常见问题速查

| 症状 | 原因与对策 |
|---|---|
| `git apply` 失败 / patch.ps1 抛错 | Flutter SDK 不是精确的 3.47.6，或 SDK 目录不是 git 仓库（用了 zip 版） |
| 报错找不到 `material_ui` / `cupertino_ui` 包 | `~/.pub-cache` 的 junction 没建，脚本在错误的缓存目录里找包；按 5.1 节建好 junction 后重跑 `pwsh lib/scripts/patch.ps1 android` |
| `flutter.sdk not set in local.properties` | 在 `android/` 下缺 `local.properties`；正常 `flutter build` 会自动生成，直接用 gradle 命令才会遇到 |
| pub get 拉 git 依赖超时 | 依赖里有 20+ 个 GitHub fork 仓库，需要能稳定访问 GitHub 的网络；必要时配置代理或 `git config --global url."https://ghproxy...".insteadOf` |
| `compileReleaseKotlin` 失败：`this and base files have different roots` | Kotlin 增量编译缓存不支持跨盘符（项目在 E 盘、pub 缓存在 C 盘）。在 `%USERPROFILE%\.gradle\gradle.properties` 里加一行 `kotlin.incremental=false` 后重跑；仍报错则先 `flutter clean` |
| 插件 Java 编译报大量"找不到符号"（如 `ChromeCustomTabsChannelDelegate`） | git 默认 `core.longpaths=false`，pub 克隆 git 依赖时路径超 260 字符的源文件被静默跳过。执行 `git config --global core.longpaths true`，删除 `%LOCALAPPDATA%\Pub\Cache\git` 后重新 `flutter pub get`（系统需已开启长路径：注册表 `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled=1`） |
| 修改 Flutter 框架相关代码后行为异常 | 换过分支或升级过 SDK 后补丁丢失，重跑第 5 步 |

## 9. 日常修改代码后的编译流程

环境搭好后，日常改动代码只需：

```powershell
flutter pub get          # 改动依赖时才需要
flutter build apk --release --split-per-abi
# 或直接连手机调试
flutter run
```

只有在**升级 Flutter SDK 版本**时才需要重新走第 5 步的补丁流程（且需上游同步更新 patch 文件）。
